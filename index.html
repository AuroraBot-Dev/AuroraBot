01 · 遇见 Aurora

她不是在等待指令。

普通 ChatBot 在消息到来后生成回复。AuroraBot 更关心一个 Agent 如何持续存在：什么时候醒来，怎样把工作 交给同伴，如何确认一件事真的发生，以及怎样在中断后继续。

I / CAUSAL

每件事都有来路

输入、思考、工具请求、执行结果和结束原因彼此相连。日志告诉你系统在做什么，因果记录告诉你为什么。

II / TOGETHER

不是一个超级 Agent

简单任务直接完成，复杂工作有界地交给同构子 Agent。每个结果回到父 Agent，协作不会变成失控的漫游。

III / RHYTHM

安静时也会醒来

持久化 scheduler 在预算内创造自主时刻。连续无事便逐步放慢，外部消息到来则立即回到你身边。

02 · 一次旅程

从一句提醒，到一次真正发生的行动。

模型可以提出行动，但不能假装行动已经发生。AuroraBot 用完整闭环连接判断与现实。

“晚上七点
提醒我开会。”

一个普通请求，一段完整的因果经历
  1. 消息唤醒独立任务

    外部输入成为环境事件。它不会和上一轮问答混成一团，而是拥有自己的预算、状态与结束。

  2. Agent 选择已授权能力

    根 Agent 理解意图，使用 Clock MCP 应用。能力名称和参数在执行前都经过明确校验。

  3. 回执证明提醒已建立

    Clock 的结构化结果回到等待中的 Agent。只有收到回执后，她才知道这件事确实完成。

  4. 时间再次唤醒她

    到点事件开启新的任务，AuroraBot 通过当前平台把提醒真正送达，而不是只在内部生成一句话。

03 · 相遇方式

从终端开始，再走向你的世界。

一个运行时，多种入口。平台负责相遇的方式，Agent 保留同一套思考与行动闭环。

Console

在本地直接交谈

最短的体验路径。输入消息、查看状态、推进任务，也可以在需要专注时关闭终端日志。

Dashboard

连接聊天界面

本仓库提供本地 Dashboard 后端、账户、会话与 WebSocket 桥接；浏览器前端由独立项目提供。

MCP & Headless

把能力带进来

连接本地或远程 MCP 应用，也可以无界面运行，让 AuroraBot 成为你自己环境中的持久 Agent runtime。

04 · 开始

几分钟，见到第一个醒来的 Agent。

需要 Python 3.12、Git、uv，以及默认模型配置对应的 API Key。

PowerShell 
# 获取项目并安装运行依赖
git clone https://github.com/AuroraBot-Dev/AuroraBot.git
Set-Location AuroraBot
uv sync --no-dev
Copy-Item .env.example .env

# 填写 DEEPSEEK_API_KEY 后，启动 Console 与 Clock
uv run --no-dev --env-file .env aurora --console --mcp

05 · 常见问题

在动手之前。

AuroraBot 与普通 ChatBot 有什么不同？
她不仅生成回复，还管理持续任务、主动唤醒、Agent 协作和真实效果回执。每次行动都处在可追溯的因果链中。
现在已经有长期记忆吗？
还没有。当前版本保留可选 Memory Agent 契约，但不把依赖包或聊天记录宣传成已经接入的长期记忆。
可以使用哪些模型？
模型角色与 Provider 由 TOML 配置。网关支持 Chat Completions tools 和 Responses 两种通道，并在调用前协商能力。
如何增加自己的工具？
实现 stdio 或 HTTPS MCP Server，在 apps.toml 声明工具，再在 agents.toml 中授予需要它的 Agent。
Dashboard 是完整网页应用吗？
本仓库包含本地后端与聊天桥接，不包含浏览器 UI。前端由独立项目维护，Console 是当前最短体验路径。
运行数据保存在哪里？
Kernel 运行态使用本地 SQLite WAL，外部 AMP 与终态归档使用 JSON。结构配置使用 TOML，密钥只来自环境变量。
