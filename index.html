Aurora / Life Process 自主生活中
  1. EVENT · ENVIRONMENT 世界发生了变化

  2. CONTEXT · PERCEPTION 理解变化意味着什么

  3. DECISION · NEXT STEP 决定回应、行动或保持安静

    需要改变环境时，通过已授权能力执行并等待回执。

01 · 遇见 Aurora

对话只是环境的一部分。

AuroraBot 不以聊天窗口为世界中心。她有持续状态、未完成的工作和自己的节律，也会平等看待来自人、时间、应用与其他 Agent 的变化。

I / LIFE

她有自己的生活

没有消息时，时间和工作仍在继续。主动节律让 Agent 在预算内自行判断是否需要思考和行动。

II / EQUALITY

变化先被理解

用户消息不会直接成为最高指令。Agent 先理解事件，再根据上下文决定回应、委派、行动或保持安静。

III / CONTROL

自主，但不失控

模型只负责判断。外部行动经过能力授权、参数校验和 Platform 执行，结果再回到因果链中。

在这一设计下，AuroraBot 提供持续任务、多 Agent 协作、可替换模型、MCP 能力、Platform 组合、持久化状态与因果记录。它们服务于同一件事：让 Agent 不只会聊天，也能长期、可靠地生活在环境中。

02 · 接入方式

一个 Runtime，多种连接方式。

Platform 负责连接不同环境，Agent 在所有入口中使用同一套认知与行动闭环。

Console

本地 Console

用于直接交互、状态查询和开发调试，是当前最简单的运行入口。

Dashboard

Dashboard 接入

提供本地聊天后端、账户、会话和 WebSocket 桥接；浏览器前端由独立项目提供。

MCP & Headless

MCP 与 Headless

通过 MCP 连接外部能力，或以无界面方式把 AuroraBot 组合进自己的运行环境。

03 · 开始

从源码运行。

需要 Python 3.12、Git、uv，以及默认模型配置对应的 API Key。

PowerShell 
# 获取项目并安装运行依赖
git clone https://github.com/AuroraBot-Dev/AuroraBot.git
Set-Location AuroraBot
uv sync --no-dev
Copy-Item .env.example .env

# 填写 DEEPSEEK_API_KEY 后，启动 Console 与 MCP 应用
uv run --no-dev --env-file .env aurora --console --mcp

04 · 常见问题

常见问题。

AuroraBot 与普通 ChatBot 有什么不同？
AuroraBot 把聊天视为环境的一部分，而不是全部。她还管理主动节律、持续任务、Agent 协作和外部效果回执。
平等看待消息，是不是意味着不听用户的？
不是。交互任务仍可优先调度。平等指消息先作为事件被理解，而不是未经判断就成为不可拒绝的系统命令。
现在已经有长期记忆吗？
还没有。当前版本保留可选 Memory Agent 契约，但不把依赖包或聊天记录宣传成已经接入的长期记忆。
可以使用哪些模型？
模型角色与 Provider 由 TOML 配置。网关支持 Chat Completions tools 和 Responses 两种通道，并在调用前协商能力。
如何增加自己的工具？
实现 stdio 或 HTTPS MCP Server，在 apps.toml 声明工具，再在 agents.toml 中授予需要它的 Agent。
Dashboard 是完整网页应用吗？
本仓库包含本地后端与聊天桥接，不包含浏览器 UI。前端由独立项目维护，Console 是当前最短体验路径。
