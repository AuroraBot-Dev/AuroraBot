01 · 特性

核心能力

  1. 声明式认知拓扑文件即配置

    认知不依赖单一"超级 Agent"，而是由多个 Agent / Router 节点通过 topology.yaml 声明式配置邻接关系。节点之间通过 FileEventBus 文件事件总线传递状态，形成文件驱动的认知管道。

  2. 三级联合记忆结构化生长

    L1 工作记忆速写当前上下文，L2 情景记忆按时间线存档并在 50 条后 LLM 自动压缩，L3 语义记忆以 ChromaDB 向量存储实现无限容量的语义检索。UnifiedMemoryManager 封装三层统一入口。

  3. 统一 LLM 网关一次接入，多模型使用

    基于 LiteLLM 的统一网关，支持 OpenAI、Anthropic、Google 等 100+ 模型提供商。一次配置，随意切换——内核节点无需关心底层模型差异。

  4. 可插拔 App 体系manifest.yaml 声明即用

    每个 App 都是独立的感知器与执行器，通过 manifest.yaml 声明命令与能力，通过 PlatformAPI 与宿主交互。接入 QQ、定时器、文件系统，只需一个 App。

  5. MCP 适配容器计划中的生态扩展

    正在设计的 MCP (Model Context Protocol) 适配容器，让任意 MCP 服务器以 App 形态接入 AuroraBot。MCP 工具被自动映射为内核可调用的命令，让 MCP 生态成为你的能力延伸。

02 · 设计理念

她如何思考

AuroraBot 不是传统的"指令-响应"机器人。她的设计哲学是——内驱式认知：持续感知环境变化，自主生成意图，主动发起行动。每一次交互不是孤立的问答，而是在记忆中持续生长的一段认知旅程。

  1. 1 内驱式决策 不等待指令，持续观察环境变化并自主生成行动意图。ImpulseGate 模拟内在冲动，让 Agent 保持活跃而不盲动。
  2. 2 文件驱动认知 所有认知状态通过 FileEventBus 在文件系统中流转——可审计、可调试、可回放。认知拓扑从 topology.yaml 中声明。
  3. 3 记忆生长 每次交互写入 L1→L2→L3 三层的联合记忆。记忆不是日志——它在 LLM 压缩、语义检索和时效衰减中持续演化。
  4. 4 高度解耦 应用层、平台层、认知引擎三层独立演进。每个 App 是独立的 Python 包，按需加载、按需启停，互不干扰。
  5. 5 模型无关 通过 LiteLLM 统一网关抽象所有 LLM 调用。内核节点通过 gateway 接口调用模型，无需关心底层是 OpenAI 还是 Anthropic。

05 · 常见问题

FAQ

AuroraBot 和普通 ChatBot 有什么不同？
普通 ChatBot 是"指令-响应"模型——等待用户输入，处理后回复。AuroraBot 是内驱式的：她持续观察环境变化，自主生成意图并主动行动。她不是在等你说什么，而是在想自己该做什么。
需要什么运行环境？
只需要 Python 3.10+ 和 uv 包管理器。认知引擎的核心 —— FileEventBus、Circuit 编排器、记忆系统 —— 都是纯 Python 实现，不依赖 Redis、消息队列等外部中间件。
可以接入哪些 LLM？
通过 LiteLLM 统一网关，支持 OpenAI (GPT-4o, o3, o4-mini)、Anthropic (Claude Opus 4, Sonnet 4)、Google (Gemini 2.5 Pro/Flash) 等 100+ 模型。也可以使用任何兼容 OpenAI API 格式的自部署模型。
如何开发自己的 App？
创建一个 Python 包，编写 manifest.yaml 声明命令与能力，实现 PlatformAPI 接口即可。App 会被 ApplicationHost 自动发现并加载。详见文档站的 App 开发指南。
三级记忆的数据存在哪里？
L1 在内存中（不持久化），L2 以 JSON 文件追加存储（50 条后 LLM 自动压缩），L3 使用 ChromaDB 向量数据库（支持持久化和无上限容量）。所有数据都在本地文件系统中。
