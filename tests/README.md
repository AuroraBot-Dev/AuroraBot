# 测试

测试按能力组织，优先保护故障后果大的行为。CI 总体覆盖率下限为 **20%**，不要求追求高覆盖率，
也不按覆盖率反向删除已有的关键测试。

## 目录

| 目录 | 关注点 |
| --- | --- |
| `cli/` | 启动、配置写入、初始化与训练入口；`app/` 验证应用安装、回滚和认证，`configs/` 验证配置边界 |
| `foundation/` | 公共契约、不可变事实、身份解析与包依赖边界 |
| `kernel/` | 能力选择、依赖装配、生命周期、插件与版本兼容 |
| `engine/` | 认知循环、原型、上下文、工具执行和委派 |
| `runtime/` | Bot 状态、未来活动、主动调度、终端输入与进程恢复 |
| `world/`、`artifacts/` | 追加式世界记录、事务、时间顺序、固定内容和路径边界 |
| `memory/`、`rhythm/` | 记忆时间正确性、检查点、节律及离线学习 |
| `ai/`、`mcp/` | 模型路由、模型版本、外部协议和连接生命周期 |
| `resources/`、`operations/` | 资源版本与范围、操作幂等、未知效果和回执恢复 |
| `support/` | 跨能力复用的 fake 和场景构造 |

专用辅助代码与对应测试放在同一能力目录。测试模块不互相导入；共享场景应放入支持模块，
通过 `tests.*` 显式导入。`conftest.py` 只提供全局离线设置和隔离配置夹具。

## 取舍

- 保留主流程、真实缺陷的回归、持久化一致性、失败回滚、幂等和未知效果、权限和路径边界、
  凭据脱敏、记忆时间边界的测试。
- 简单字段转发、默认值、展示格式和常量通常不单独测试；能由已有行为场景说明的，不重复铺用例。
- 参数化用于真正不同的行为分支，不穷举同类输入来增加用例数。不测试辅助函数本身，不为覆盖行数添加断言。
- 测试必须离线、确定且可重复；外部模型和工具使用 fake，学习机制使用受控 CPU 模型，
  世界存储使用临时 SQLite。

## 运行

```bash
uv sync --locked --group dev
uv run aurora check --fix
uv run pytest tests/engine tests/world -q
uv run pytest tests/cli/app/test_install_transaction.py -q
uv run aurora check --test --coverage
```

日常检查不采集覆盖率；最后一条命令用于按需测量及 CI 门槛检查。
