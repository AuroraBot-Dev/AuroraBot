# 0302：组合机制与能力自描述

状态：现行

日期：2026-09-11

## 1. 动机

早期组合机制虽然已经分层，但分层位置不彻底：机制本身不含任何具体能力名，却与项目策略放在同一层；每项能力都要在项目层再写一份装配描述，能力实现与其装配描述分离，第三方无法在不修改宿主的情况下接入。

本 RFC 规定组合机制与能力自描述的分工，使机制成为可被任何包（含第三方）依赖的无项目语义叶子，并让能力在自身边界内自描述。

## 2. 目标与非目标

目标：

1. 组合机制与项目语义彻底分离，成为可被任何包依赖的叶子。
2. 每项能力在自身边界内自描述：声明提供什么、需要什么、贡献什么、如何构造与何时运行。
3. 产生任何效果前完成冲突裁决、缺失依赖检测、循环依赖检测与拓扑排序，失败即拒绝启动并给出诊断。
4. 内置能力与第三方使用同一协议；第三方无需修改宿主即可接入。
5. 项目层不再持有任何运行期组合，只保留命令分发与配置解析。
6. 保留类型安全：以契约类型为能力身份。

非目标：

- 不引入第二套认知运行模型。组合机制是组合机制，不是任务、邮箱、活动或续跑。
- 不引入通用事件总线。模块间同步协作靠注入的契约实例；事实变更只能经世界线提交。
- 不引入非单例作用域。当前只有进程内单例能力；没有真实用例前不注册变化轴。
- 不做运行时热插拔。装配在启动期完成，运行期冻结。
- 不做机制协议兼容性标志与版本协商；先按单一版本推进。
- 不改变最小运行语义、消息角色、模型与工具端口、世界语义或配置拓扑。

## 3. 机制边界

组合机制只承担机制职责：

- 以契约类型为键的类型化能力目录与读取；
- 模块声明；
- 解析与装配：冲突裁决、缺失依赖、环检测、拓扑排序；
- 生命周期：准备 → 构造 → 冻结只读装配 → 激活 → 后台运行 → 关闭；
- 发现：随发行包、本地插件目录与入口点。

依赖约束：

- 机制只依赖标准库、通用工具与通用契约值类型。
- 机制不 import 任何具体能力实现或项目层。
- 机制以类型为能力身份，不硬编码任何能力名。

## 4. 能力身份与公共契约

能力身份就是公共契约类型本身。模块通过契约类型声明依赖与提供，因此第三方只需依赖公共契约即可实现或消费能力，无需引用宿主私有键对象。

- 公共契约同时持有公共多值贡献点；贡献点是稳定公共事实，第三方可向既有键追加同类型值。
- 读取能力使用泛型；可选依赖使用可选读取。能力缺失是装配期错误，不是运行期错误。
- 一个实例可实现多个契约：构造器返回同一对象，机制把它登记到该模块声明的全部契约下。

## 5. 能力自描述

每项能力在自身边界内声明，能力实现与装配描述同处一处。

规则：

- 声明入口把一个构造器登记为模块；声明中提供、需要、贡献、消费均为契约类型或贡献键，不用字符串。
- 构造入口经上下文登记本模块产出的实例与贡献；机制在返回后校验声明全部已登记，且每个能力只有唯一提供者。
- 消费某贡献点表示读取其完整冻结序列；机制据此自动依赖全部已发现贡献者，零贡献合法。
- “构造无依赖、但顺序有依赖”必须与“构造依赖”分开表达。
- 纯副作用模块允许不提供能力；既不提供也无贡献是配置错误。
- 生命周期阶段语义：准备（在构造前执行，可返回清理函数）→ 构造 → 冻结只读装配 → 激活（按顺序约束执行）→ 后台运行 → 关闭（逆序，含准备清理）。

## 6. 解析与装配

1. 收集全部模块声明，按名称去重。
2. 构建提供者目录；同一契约类型被多个模块提供时按优先级降序裁决，平局立即失败并列出全部候选。
3. 校验每个非可选依赖都有提供者；缺失即失败并输出“模块 → 缺失契约”。可选模块在缺失时整体跳过。
4. 由依赖与消费构建有向图并拓扑排序；检测到环时输出完整环路。
5. 按序执行准备与构造；冻结唯一只读装配。
6. 激活按顺序约束扩展后的拓扑序执行；后台运行作为任务启动。
7. 关闭先取消后台任务，再逆序执行模块关闭与准备清理。准备失败回滚已构造模块。

诊断要求：冲突输出候选与优先级，缺失输出模块与契约，环输出完整环路，启动失败输出失败模块、异常与已启动模块列表。

## 7. 发现源

发现源提供模块声明。内置源扫描随发行包；目录源扫描项目内被忽略的本地插件目录；入口点源读取约定的插件入口组。

确定性：内置源按名称排序；目录源按路径排序；入口点按名称排序。发现顺序只影响同优先级冲突的报告顺序，不产生隐式覆盖；跨源冲突仍必须由优先级显式裁决。第三方插件在进程内与宿主同权限运行，这是有意的信任边界，不做进程隔离。

## 8. 配置边界

- 项目层只负责把配置解析为只读对象，并暴露只读目录供查看；项目层不构造任何运行期实例，也不持有装配逻辑。
- 配置形状由能力自身拥有；解析机制在项目层。能力经注入的只读配置访问契约读取自己的配置，不 import 项目层。
- 项目层不得让 TOML 字段名进入能力实现。

## 9. 门面与启动

- 进程门面自描述为消费运行器、能力目录、终端、世界与绑定贡献、提供门面工厂的模块；装配入口发现声明、执行统一生命周期、从冻结装配创建门面、驱动前台与逆序关闭。
- 命令层只做环境、配置、日志、信号与调用装配入口；不持有协作者清单，也不写装配分支。
- 启动准备不产生世界事实；由声明得到的顺序必须等价于：世界初始化 → 外部工具发现与贡献冻结 → 工具目录冻结 → 目录交叉校验 → 装配冻结 → 主动节律游标固定 → 外部事件入口激活 → 后台启动。

## 10. 依赖方向

```text
通用工具  通用契约              ← 叶子（机制与任何能力可用）
组合机制                        ← 机制叶子
能力实现 + 自描述模块 + 配置形状
进程门面
命令分发与配置解析              ← 项目层
```

- 项目层不再包含机制或运行期组合。
- 下层不得 import 上层。

## 11. 验收标准

- [ ] 组合机制运行时只依赖叶子，无领域实现 import。
- [ ] 项目层不再包含任何运行期组合或协作者清单，只保留命令、配置与项目工具。
- [ ] 每项能力自描述唯一模块；能力身份是契约类型，无字符串能力键。
- [ ] 依赖边界测试确认下层不导入上层。
- [ ] 新增第三方插件无需修改宿主代码即可经本地插件目录或入口点接入。
- [ ] 冲突、缺失依赖、循环依赖在启动前失败并输出可定位诊断。
- [ ] 不存在通用事件总线、非单例作用域、运行时热插拔或机制版本协商。
- [ ] 全量离线测试与质量检查通过。

## 12. 已定决策

- 配置归属：配置形状下沉能力包，TOML 解析留在项目层；类型在能力层、解析在项目层，能力经只读配置访问契约读取。
- 每项能力在其自描述模块中定义并导出唯一模块声明；包入口不感知组合。
- 本地插件目录与入口点的发现细节在实现时补充；命名冲突一律失败并报告，不做隐式覆盖。
