# 认知与恢复

## 主体状态

`BotStateStore` 从主体自己的世界域投影目标、恢复检查点与未来活动。目标包括完成条件和状态；检查点记录阶段、已确认结果、约束、待完成动作、开放问题与证据引用。状态修改携带预期版本，重复命令不会重复写入，过期版本要求重新读取后判断。

`BotClock` 与主体状态分别装配。时间服务兑现 Bot 的持久安排，通过 `CognitionLauncher` 启动一次认知，完成后提交安排的结果。重启会核对运行事实：已完成的安排不重复交付；已经开始而效果未知的认知标记为中断，保留待核对依据，不自动重放外部行动。已登记安排不受批量节律开关影响。

## 认知入口与执行策略

Bot 的运行入口接受 `CognitionRequest`，返回只含运行身份、输出和错误的 `CognitionResult`。时钟、节律和终端只读取这个结果，完成一次执行不等于完成持久目标。`CognitionRunner.execute()` 可使用不同执行策略；它负责持久登记开始和结果，中断保留未确认状态，禁止自动重放未知外部效果。

`AuroraRuntime` 串行交付请求，保持环境事件可提交；只累计运行数量与状态，不缓存每次执行的节点图。文本观察器按单次执行创建，完成后释放。需要查询历史时读取世界记录。

默认 `CognitionEngine` 使用深度优先循环，`AgentTree` 只组织这项策略的委派上下文；它不再作为 Bot 的运行入口或返回值。树的状态从入口节点推导，不另存一份生命周期状态。其他执行器无需创建树。

## 默认委派循环

root 与 child 使用同一种不可变 `AgentNode` 和同一单循环。每个节点持有创建时冻结的 `AgentDefinition`，包含确定的原型版本、Prompt、模型、可见工具和可委派原型。已有节点不追随同名目录变化；`ModelRequest` 显式携带该节点的模型端点。

一次循环依序执行：

1. 选择 ready node，按确定世界前缀读取主体状态和记忆。
2. `PromptAssembler` 组装四角色上下文，工具定义通过原生 tools 字段进入请求。
3. `Model.complete` 返回 assistant 消息，追加到节点。
4. 有工具调用时检查范围、可见性和未披露的世界变化，登记请求并执行；结果形成配对的 tool 消息。
5. 内建 `aurora:tool/definition/delegate` 校验委派参数并返回 `DelegationRequest`；engine 校验允许列表和树上限后创建 child，结束时以 tool 结果恢复 parent。
6. 无工具调用时核对世界增量，child 完成后返回 parent；root 的最终文本在登记输出事实后结束默认执行器的本次认知。

当前是确定性的深度优先单循环，同一树中不并发执行模型或工具。模型失败使当前节点失败；普通工具的失败或 unknown 作为 tool 错误消息返回，由 Bot 判断后续动作。模型网关允许总截止时间内的有限重试，并关闭 SDK 隐式重试；外部工具效果不自动重试。

## 上下文与记忆

`ChatMessage` 只有 `system`、`message`、`assistant`、`tool` 四种领域角色，只有 Provider adapter 将 `message` 映射为外部协议的 `user`。

`PromptAssembler` 不读取数据库、记忆服务或模型；调用方把 `MemorySnapshot` 显式传入。字符容量先为可见工具的完整定义预留空间，再保留系统片段、主体检查点、必要证据、原始输入和最新完整交互。可选经历与较早对话使用剩余容量；工具调用及对应结果整组保留或移除。必要内容超限会在模型或行动效果发生前报错，不截断关键约束继续执行。字符容量是输入代理计量，不等同于实际模型 token 数。

记忆读取同时受全局游标、事件发生时间和获知时间约束。近期索引、内容与实体匹配、目标依赖、支持或反驳关系、显式标记等候选经过独立策略评分，再补齐必要依赖、去重和组装集合。推荐内容、必要证据、实际载入和已进入消息历史的来源分别审计，展示不等于采用或收益。

节点的 `memory_scopes=None` 使用配置允许的范围，空集合不召回任何域，非空集合限定读取域；child 继承范围。显式事件和 Console 使用触发事实的域，批量节律可读取完整配置范围。运行台账按域目录分类，不默认混入环境经历。Bot 可通过公开操作调整查询、选择焦点目标、展开原始来源和提交修正反馈。

`src/aurora_bot/rhythm` 的 GRU 持续接受廉价压力、时间和主体特征，输出是否推理、下一次检查时间与新隐状态。`src/aurora_bot/cadence` 保存真实策略版本、参数和循环状态，并处理环境变化及到期时间；自己的记账不自动放大事件压力。Bot 的目标与待核对动作提供内生压力，安静环境也可以唤起认知。

`src/aurora_bot/memory_model` 的 TGN 根据有时间顺序的图交互为记忆排序。权重固定，动态图状态在线更新；内容和世界事实独立保存。检查点是可重建的加速投影，启动后仍核对实际查询前缀，模型或范围不兼容时从原始事实重建。当前索引与图投影仍随保留历史增长，输出有界不表示历史存储或候选计算恒定。

## 世界事实与行动边界

`WorldJournal` 是唯一追加式事实权威。每条提交拥有稳定 ID、发生时间、获知时间、全局 cursor 和各 scope 的递增 sequence。`WorldFrontier` 仅表示已经披露的域进度；提交归属由提交方决定，world 不推断业务语义，也不自行产生事件。

节点的观察范围与记忆范围分开表达。工具声明的 observe 域扩展观察，publish 域和内部台账只推进因果进度。执行工具批次和发布 root 文本前检查未披露增量；还有页面时不执行批次，用配对的 deferred 结果让 Bot 阅读，再明确选择基于已知前沿继续。已经封口的批次不会因随后并发到达的新提交永久饥饿。

世界读取工具为 `aurora:tool/definition/world_read` 和 `aurora:tool/definition/world_trees`，只读取显式范围和有界页面。运行中产生的模型请求记录实际端点、提供方、Agent、Prompt、工具和记忆版本，可按归档引用复核当时输入。

普通工具通过 `Tool` 端口执行，结果为 `succeeded`、`failed` 或 `unknown`。unknown 表示请求可能已经产生效果但无法确认，必须原样交给模型并保留事实。领域操作路由另外保存请求、接受状态和回执；只有明确声明安全重试的操作允许恢复执行，未知外部效果先核对实际状态。

工具、资源、模型、过程定义都使用命名空间身份。运行实例保存独立身份和确定过程版本；发现实例时读取当前投影，历史版本读取固定世界截点。`started` 只是存在开始事实而没有规范终态，不是当前进程存活证明。

Console 渲染只是本地呈现，不构成对外发送。对外回复必须由 Bot 调用可见的发送工具；MCP 业务事件只追加世界，不能直接启动认知或绕过工具执行效果。
