# RFC 0001：架构基准与最小因果闭环

状态：已接受
日期：2026-07-11

## 背景

旧系统的认知、平台、记忆、输出和运行时边界相互交叠，导致“产生文本”“调用工具”“效果已经完成”无法被可靠区分。vNext 从可审计的因果闭环重新演化。

## 决策

### 核心原则

Kernel 负责事件、状态、图调度、周期与因果边界；Node 负责认知；Platform 负责环境感知与效果执行。任何一层不得替代另一层的职责。

### 模块边界

| 位置 | 责任 |
| --- | --- |
| `src/kernel` | AMP 接管、Kernel record、工作区、图、周期、状态和因果限制。 |
| `src/ai` | 宽泛模型网关：模型角色、能力协商、调用、计费、节流与中断。 |
| `src/localhost` | CLI 与 Dashboard 共用的业务用例和开发者调试能力；不提供 HTTP 路由。 |
| `src/dashboard` | Dashboard 的后端路由/API 适配；只依赖 `localhost`。前端不由本仓库管理。 |
| `src/platform` | 平台生态适配、AMP 归一化、能力目录和效果执行。 |
| `src/apps` | 内建原生 AMP-MCP 应用，经 Platform 接入。 |
| `src/nodes` | 自包含的内建认知节点。 |
| `src/utils` | 无上层依赖的纯通用工具。 |

记忆、沙箱和提示词不是 vNext 内核的预设顶层子系统。它们先以节点或节点能力的形式出现，稳定后才可抽取为可复用实现。

### 最小运行图

第一条可运行图只包含一个认知节点：

```text
AMP ingress → builtin.decide → effect.requested
```

Kernel 在调用 `builtin.decide` 前必须提供：当前 AMP 输入、固定版本的 `SOUL.md`、当前情景上下文或内核快照、已声明能力的快照，以及此节点获准使用的模型角色和能力范围。

`builtin.decide` 只能发布声明过的事件；不得直接调用 Platform client、修改共享工作区或自行执行外部效果。

### 效果闭环

`effect.requested` 是决策，不是执行成功。Platform 是唯一可以执行该效果的一层，并且必须以新的 AMP `effect.succeeded` 或 `effect.failed` 事件回写结果。效果回执在下一周期进入图。

### 周期与自环

一个周期只消费该周期开始时已经就绪的记录集合。本周期产生的记录最早在下一周期调度。所有记录必须具有因果父级、轮次/跳数或预算限制；任何图环必须显式声明其推进条件和最大界限。

`system.tick`、反思、探索和效果反馈都是普通事件。自发性不得绕过能力授权、预算、冷却、优先级或终止条件。

### 工作区

Kernel 工作区只有三个顶级业务目录：

```text
data/kernel/inbox/     # 平台投递的 AMP JSON
data/kernel/process/   # 已接管记录、快照、租约、中间产物和效果请求
data/kernel/archive/   # 已完成、失败、过期或压缩后的记录
```

这是共享可见工作区，不是任意共享可写目录。节点通过 Kernel API 创建事件或更新被授予的状态键；节点间协作优先采用追加事件而非覆盖文件。所有生产者必须先写临时文件，再原子改名。

## 非目标

- 不在最小闭环中复刻旧版三级记忆、自动梦境、热重载或内建沙箱。
- 不让 Kernel 理解 MCP、QQ、Discord、OneBot 或任意平台私有对象。
- 不把 Dashboard 变成第二个运行时。

## 验收标准

1. 一个 AMP 输入能产生一个可审计的 `effect.requested`。
2. Platform 的成功和失败回执均以新事件在下一周期进入图。
3. 每条记录可追溯到输入、产生它的节点和因果父级。
4. 未授权节点不能直接执行效果或写入其他节点状态。

## 迁移影响

`legacy/` 中的实现只能按本 RFC 的边界逐项迁移；不存在“整体搬回 `src/`”的迁移路径。
