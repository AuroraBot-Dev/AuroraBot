# 0203：Agent 自由与运行时边界

状态：已接受
日期：2026-07-30
来源：收紧 RFC 0200/0201 中未明确区分的认知自由、资源保护与效果安全边界

## 问题

现行 ToolAgent 与模型网关包含一组并非安全边界的行为管制：强制关闭并行 Tool call、把一次模型响应截成单一
主动作、把空文本改写为 `no_action`、禁止控制能力与其他 Tool call 共存，以及在任意外部输入到达时取消所有
自主 Task。这些规则替模型决定了行动数量、组合、时机和终止方式，与 Agent 中心原则冲突。

## 决定

### 认知自由

- Prompt 中的身份、表达习惯和交互约定是 Bot 正常交互所需的显式人格配置，继续作为 stable system prompt。
- Agent profile 暂时固定 `model_role`；本 RFC 不开放模型自选角色。
- 模型响应中的文本和全部 Tool call 都是事实，运行时不得截断、伪造拒绝结果、改写为空动作，或仅因调用数量和
  组合方式而判定失败。
- `parallel_tool_calls` 由模型请求传递给 Provider。网关不得全局禁止，通道适配器不得覆盖调用方选择。
- Agent handler 可以把同一模型响应中的多个 Tool call 组成可恢复链或批次；这是执行机制，不得改变、丢弃或
  拒绝模型选择。控制能力与外部效果能力可以出现在同一响应中，并最终全部执行。
- 运行时不得向外部 Capability 的 Tool schema 注入参数。只有 Capability 自己公开声明
  `runtime_completion` 时，平台回复工具才可以暴露任务结束标记；该标记属于显式平台契约，不适用于任意 Tool。
- 一次 `AgentDecision` 仍是一项原子状态迁移。这个事务边界不限制一次模型响应中的动作数量；多个 Tool call
  通过可恢复链分别提交，全部完成后再恢复模型。

### 运行时边界

- Engine 只约束真实外部效果：Capability 必须存在、Agent 必须获授权、参数必须符合公开 schema、回执必须匹配
  已持久化请求，并继续保证幂等、租约、因果记录和崩溃恢复。
- 模型调用数、Tool 调用数、Task 时长、并发数和上下文字符数属于资源上界，可以终止超额工作，但不得在额度内
  改写模型决策。
- 委派深度、总 Agent 数和并发 Agent 数属于资源上界；profile 的 `can_delegate` 与 `child_profiles` 继续作为
  明确配置的效果授权。
- 空文本保持为空文本。是否沉默由 Prompt 和模型决定，运行时不生成 `no_action` 或替代完成文案。
- 新的外部 AMP 只唤醒对应工作，不自动取消正在运行的自主 Task。显式取消、Task 预算耗尽和进程关闭仍可终止它。

### 保留的接纳边界

RFC 0202 的 Triage `process`、`defer`、`discard` 是用户明确选择的 Inbox 接纳策略，不属于 Root 决策过滤的
隐藏规则，继续保留并通过因果日志审计。

## 结果

Prompt 负责“Bot 想怎样互动”，LLM 决定“这一轮做什么”，Engine 只负责“这些效果是否真实、获授权且在资源
上界内”。模型可以在一个响应中选择多个 Tool call；外部输入不会无条件打断自主工作；运行时不再制造额外的
认知结论。
