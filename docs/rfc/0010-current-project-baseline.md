# RFC 0010：当前项目基线与历史归档

状态：已接受
日期：2026-07-15

## 背景

AuroraBot 的因果事件架构、首轮认知闭环、主动调度、模型工具调用、MCP Platform、本地调试入口与常驻
Bot 入口均已有已接受 RFC 和可运行实现。继续在工作树中保留一份不参与构建、测试或运行的历史源码快照，
会让读者误以为仓库同时维护两套架构，也会使 README、贡献指南和代码注释长期围绕迁移过程而不是当前系统。

历史实现及社区资料已经存在于 Git 历史和项目外部归档。它们可以用于考证，但不是当前仓库的目录、API、
配置或设计基准。

## 决策

### 单一当前实现

AuroraBot 工作树只保存当前实现。项目不设置 `legacy/`、`old/` 或其他历史源码镜像目录，也不在忽略规则中
预留此类目录。需要查阅过去实现时使用 Git 历史或独立归档；任何历史路径都不得成为运行时导入、测试
fixture、扩展接口或文档链接。

### 当前项目叙事

README、贡献指南、首页、包级 README、AGENTS 指令和源码说明必须直接描述当前 AuroraBot，不再使用“重建
阶段”“冻结旧系统”“等待入口完成”或“从旧实现迁移”等过渡叙事。`AuroraBot vNext` 不再作为对外项目名；
需要区分架构版本时引用具体 RFC、AMP 版本或项目版本号。

已接受 RFC 可以记录决策关系，但规范页面必须以当前有效契约为主体。RFC 0001、0004、0006、0007 和 0009
中关于历史目录、冻结入口和提取模块的迁移说明由本 RFC 取代；其当前职责分别保持为架构边界、扩展契约、
本地调试 API、本地控制台与配置门面、常驻 Bot 入口。

### 社区与历史资料

社区行为准则、贡献流程和许可证继续作为当前项目规范。外部归档仅用于保留过去社区资料和实现记录，不是
构建依赖，也不能覆盖 `docs/rfc/`、当前代码或当前配置。引用外部资料形成的新设计，仍须通过 RFC 和测试进入
仓库。

### 文档一致性

- 中文、英文和日文 README 必须描述同一运行图、目录和启动方式。
- 中文、英文和日文贡献指南必须使用同一环境要求、分支流程和质量检查。
- 包级 README 只展示当前公开 API 和 TOML 配置，不展示未启用架构或环境变量模型路由。
- RFC 索引、项目布局和入口说明必须随已接受契约同步更新。
- CI 或文档检查应拒绝重新引入历史源码目录以及已被本 RFC 取代的项目叙事。

## 非目标

- 不删除 Git 历史、版本标签、贡献者记录或社区公约。
- 不把外部归档复制回仓库。
- 不因清理叙事而自动启用记忆、沙箱、Dashboard 前端或新的平台适配器。
- 不改变 RFC 0001—0009 已定义且未被本 RFC 明确取代的运行时契约。

## 验收标准

1. 工作树和忽略规则中不存在 `legacy/`。
2. 当前源码、测试、配置和文档不导入或链接历史源码路径。
3. README 和贡献指南准确描述 `bot.py`、`aurora` CLI、首轮认知图与当前质量命令。
4. 全文扫描不再出现“重建阶段”“冻结旧系统”“旧入口不可用”等已失效描述。
5. 测试、Ruff、格式检查和 Pyright 继续通过。

## 取代关系

本 RFC 取代以下条款：

- RFC 0001 的迁移影响和以历史系统为主体的背景叙事。
- RFC 0004 对历史目录和迁移期 YAML manifest 的说明。
- RFC 0006 关于 Bot 入口尚未定义的迁移说明。
- RFC 0007 的提取模块兼容叙事；保留本地控制台和共享配置门面的有效契约。
- RFC 0009 关于冻结入口和历史目录的说明。
