# RFC 0011：当前项目基线与源码归档边界

状态：已接受
日期：2026-07-15

## 背景

AuroraBot 的因果事件架构、首轮认知闭环、主动调度、模型工具调用、MCP Platform、本地调试入口与常驻 Bot
入口均已有已接受 RFC 和可运行实现。在当前工作树中并置其他架构世代的源码快照，会让目录、API、配置和文档
出现多个相互冲突的解释。

项目演进记录由 Git 保存，社区资料另有项目外归档。它们可用于考证，不参与当前构建、测试、运行和设计判断。

## 决策

### 单一当前实现

AuroraBot 工作树只保存当前实现，不设置其他架构世代的源码镜像目录，也不通过忽略规则保留此类目录。
删除镜像目录前必须确认其内容可由 Git 或明确的项目外归档恢复；删除后不修改项目外归档。

当前目录职责以 RFC 0001 和根目录 `AGENTS.md` 为准。未进入当前模块边界的功能，只能通过新 RFC 与实现加入，
不能通过复制归档源码隐式恢复。

### 当前叙事

README、贡献指南、首页、包级 README、AGENTS 指令和源码说明必须直接描述当前 AuroraBot：

- 项目名统一为 AuroraBot，不使用阶段性代号。
- 根目录 `bot.py` 是可运行的常驻入口，本地调试入口为 `uv run aurora`。
- 默认认知图、模型通道、主动节律与首轮边界以 RFC 0008 为准。
- 文档必须准确说明当前组件边界与可运行入口，不使用阶段性状态描述。

RFC 0001、0004、0006、0007 与 0009 中的过渡期说明由本 RFC 取代；它们的当前职责分别保持为架构边界、
扩展契约、调试 API、控制台/配置门面和常驻入口。

### 社区资料

`README*.md`、`docs/CONTRIBUTING*.md`、`CODE_OF_CONDUCT.md`、`LICENSE` 和 `AGENTS.md` 是当前社区入口。
项目外归档中的社区规范只用于核对许可证、分支流程和多语言内容，不具备规范优先级，也不得覆盖已接受 RFC。

三语入口应保持相同事实：当前能力、启动命令、目录结构、质量命令和安全边界不得因语言不同而冲突。

## 验收标准

1. 工作树只包含当前模块边界内的源码和测试。
2. 忽略规则不保留其他架构世代的源码目录。
3. README、贡献指南、首页、RFC 索引、包级 README 与源码说明描述同一套当前架构和入口。
4. 三语文档中的启动、测试与贡献流程一致。
5. 自动化检查能够阻止阶段性项目名、不可运行入口等失效描述重新出现。
