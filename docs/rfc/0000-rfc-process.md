# RFC 0000：RFC 过程与规范语言

状态：已接受
日期：2026-07-11

## 决策

1. `docs/rfc/` 是 AuroraBot 的唯一架构权威。
2. 已接受 RFC 使用“必须”“不得”“可以”表达可验证要求；模糊愿景不得伪装成契约。
3. 架构、事件、配置、扩展和模型网关的改变必须先有 RFC 变更，再有实现变更。
4. 已接受 RFC 的实质性变更必须新增 RFC 并标记被取代者；只允许直接修正错别字、链接和不改变语义的表述。
5. 每份 RFC 必须至少包含：背景或目标、决策、约束或非目标、验收标准，以及与现有契约的关系。

## 验收

- README、配置样例、贡献指南和 `AGENTS.md` 必须链接或服从本目录。
- 每个已接受的运行时契约必须最终具备自动化测试。

## 非目标

RFC 不替代 API 参考、教程、发布日志或代码注释。
